# design-sync notes — Wayshrine Compass

Repo-specific gotchas for future syncs. Read this before re-running.

## Shape: this is an app, not a component package

- No Storybook, no `dist/`, no package exports. `shape: "package"`, and the converter
  is pointed at **`.design-sync/entry.tsx`** — a committed barrel that re-exports the
  real components from `src/`. Nothing is reimplemented there; if a component is added
  to `src/components/`, add it to the barrel **and** to `cfg.componentSrcMap`.
- `--entry` is mandatory. Without it the converter looks for
  `node_modules/wayshrine-compass/package.json` (npm won't self-install) and dies with
  ENOENT.
- `cfg.componentSrcMap` pins all 11 components explicitly. Discovery finds **zero**
  otherwise: there is no `.d.ts` tree to scan, so `[ZERO_MATCH]` fires and the build
  degrades to "tokens-only DS".
- Compound sub-parts (`CardHeader`, `SelectItem`, `TableRow`, …) are exported from the
  barrel so they land in the bundle (36 window exports), but are deliberately **not**
  in `componentSrcMap` — they'd each get their own near-empty card.

## The build order that matters

`globals.css` is Tailwind v4 *source*, not compiled CSS. `cfg.cssEntry` points at
`.design-sync/.cache/tailwind.css`, which is generated by `cfg.buildCmd`:

```
node .ds-sync/node_modules/@tailwindcss/cli/dist/index.mjs \
  -i .design-sync/tailwind-entry.css -o .design-sync/.cache/tailwind.css
```

**Always run buildCmd before `package-build.mjs`, and re-run it after editing any
preview.** Tailwind only emits classes it finds in scanned source; a new utility used
in a preview renders unstyled until the CSS is recompiled. `lib/preview-rebuild.mjs`
does *not* re-run Tailwind — after a targeted preview rebuild that introduced new
classes, do a full buildCmd + `package-build.mjs` pass.

`@tailwindcss/cli` is installed into `.ds-sync/` (gitignored) alongside the converter
deps, pinned to the repo's tailwind version (4.3.3). A fresh clone must reinstall it.

## The safelist is the design agent's utility surface

`.design-sync/tailwind-entry.css` carries a large `@source inline(...)` block. This is
not decoration: without it the stylesheet contains only the ~narrow set of classes
`src/` happens to use, and every layout the design agent composes (`bg-accent`,
`md:grid-cols-2`, `gap-8`) would silently render unstyled. Compiled output is ~550 KB.

- Keep the safelist and the class families listed in `conventions.md` in sync — the
  header tells the agent exactly what it may use.
- **Do not safelist `font-serif`**: its default stack names Cambria, which the bundle
  can't ship, and validate fails with `[FONT_MISSING]`.
- **Do not safelist `rounded-xs/2xl/3xl`**: they compile to
  `border-radius: var(--radius-2xl)`, and this theme only defines `--radius-sm/md/lg/xl`
  from `--radius`. They'd render square with no warning.

## Fonts

`globals.css` maps `--font-sans` → `var(--font-geist-sans)`, which **next/font defines
only at app runtime** via the `layout.tsx` className. For the bundle, the Geist and
Geist Mono woff2 files plus a hand-assembled `@font-face` sheet live in
`.design-sync/fonts/` (committed) and are wired via `cfg.extraFonts`. They were
harvested from this repo's own `.next` build output — the `@font-face` rules are
verbatim, only the `url()` paths were rewritten, and a `:root` block defining
`--font-geist-sans` / `--font-geist-mono` was appended.

## Previews

- Dark-first DS, but the preview scaffold hardcodes `body{background:#fff}` (in
  `lib/emit.mjs`, which must not be forked). Every authored preview therefore wraps its
  cells in a `Surface` div: `-m-6 bg-background p-6 text-foreground`. The `-m-6` cancels
  the card's 24px padding so the dark surface is full-bleed. **Keep this pattern in any
  new preview** or the component renders near-white text on white.
- Because `Surface` is full-width, every component trips `[GRID_OVERFLOW] wide`. All 11
  carry `cfg.overrides.<Name>.cardMode = "column"`, which is the right presentation
  here anyway. A new component will flag on first validate — apply `column` and move on.
- `cfg.provider` is `PlatformProvider`; `BuildGuidance` and `PlatformToggle` call
  `usePlatform()` and render blank without it.
- `BuildGuidance` renders native `<details>`, collapsed on first paint. Its `Opened`
  cell uses a small `useEffect` that sets `d.open = true` — the real rendered output,
  not a mock.

## Grouping

The converter puts everything in `general`. `.design-sync/docs/<Name>.md` are
frontmatter-only stubs (`category:`) that regroup the 11 into actions / forms /
data-display / layout / wayshrine, wired via `cfg.docsDir`. They carry no prose, so the
`.prompt.md` bodies are still synthesized from the `.d.ts` + authored preview examples —
verified after the change.

## Known render warns

None. The final build is warning-free: render check 11/11, no `[FONT_MISSING]`, no
`[GRID_OVERFLOW]`, no `[TOKENS_MISSING]` above threshold.

Benign undefined vars in the compiled CSS (do not chase): `--default-font-*-settings`
(Tailwind preflight, used with inline fallbacks) and `--radix-select-*` (set at runtime
by Radix when a Select opens).

## States that can't render statically

- `PlatformToggle` in **console** state. Platform lives in React context seeded from
  `localStorage` in a `useEffect`; a preview can't force it without a module-level side
  effect that would leak into every cell on the page. Only the PC-active state is shown.
- `Select` in its **open** state — Radix portals the content to `document.body`, which
  escapes the card. Only trigger states (placeholder / selected / disabled) are shown.

## Re-sync risks — what can go stale

- **The 7 shadcn primitives are unused by the app.** `grep -rn "@/components/ui" src/app`
  returns nothing. Their previews were composed from component source + `.d.ts` with
  domain-realistic ESO content, not ported from real usage — so if the app starts using
  them differently, the cards may drift from house style. The 4 Wayshrine components
  *are* used (build detail page, `layout.tsx`) and their previews mirror that usage.
- **Preview data is inlined.** `BuildGuidance` / `PlatformProvider` blocks are copies
  shaped after `src/data/builds.ts::guidanceFor`, and `FreshnessBadge` objects are
  shaped after `computeFreshness`. If `GuidanceBlock` or `Freshness` changes shape, the
  previews still compile but stop being representative — re-check them against
  `src/lib/types.ts` and `src/lib/freshness.ts`.
- **Fonts are pinned to hashed `.next` filenames.** They're copied into
  `.design-sync/fonts/`, so they survive a `.next` wipe. But if the app changes font
  family or subsets, re-harvest rather than assuming these are current.
- **Tailwind version coupling.** The safelist syntax (`@source inline`) is v4-only, and
  `@tailwindcss/cli` is pinned to 4.3.3 to match the repo. A Tailwind major bump needs
  the safelist re-checked for renamed utilities.
- **`.next` must exist for a font re-harvest.** It was present from a prior build this
  run; a clean clone would need `npm run build` first.
